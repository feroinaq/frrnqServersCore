# frrnqServersCore — состояние проекта

VideoPlayer для fSC 1.3 завершён. Пользователь подтвердил работу локальных и удалённых MP4 на предыдущем этапе.

## Среда и границы изменений

- Minecraft 1.12.2, Forge 14.23.5.2860, Java 8, Gradle Wrapper 4.9 и LWJGL 2. В `build.gradle` указан ForgeGradle `3.+`, в проверенной среде разрешалась версия 3.0.197. MCP mappings — `snapshot_20171003-1.12`.
- Перед изменениями прочитать `AGENTS.md` и проверить `git status` и `git diff`. Незакоммиченные изменения могут содержать рабочую реализацию.
- Существующие модули — WorldRules, DeathLimit и HUD жизней, TeamSpawn и TeamStatusHUD, ResourceChests, AirDrop, WorldBorderNotifications и уведомление о начале игры. VideoPlayer подключён к тому же моду и корневой команде `/fcore`.
- Сборка `.\gradlew.bat build` завершилась `BUILD SUCCESSFUL` за 12 секунд. Артефакт — `build/libs/modid-1.0.jar`. Проверка на собранных классах подтвердила точный отказ для `play` и `preload`, сохранение активной сессии и приём разрешённых HTTPS MP4.

## Архитектура VideoPlayer

Исходники находятся в `src/main/java/com/frrnq/serverscore/`.

| Компонент | Ответственность |
|---|---|
| `video/VideoCommand`, `video/VideoSessions` | Ветка `/fcore video`, одна глобальная сессия, права OP 2+, расчёт готовности, назначение старта и статистика. Сервер обрабатывает только управляющие данные. При перезапуске сессия сбрасывается. |
| `video/VideoDomains`, `video/PinnedVideoHttps`, `video/VideoCache` | Проверка URL, фильтрация сетевых адресов, HTTPS с проверкой TLS, скачивание и кеширование на клиенте. |
| `video/RemoteVideoClient`, `video/VideoPreparationHud` | Клиентское состояние сессии, замеры часов, отчёты готовности, поздний вход, повторная синхронизация и административная панель. |
| `video/VideoPlaybackManager`, `video/VideoPlayback` | Управление фоновым выполнением и очисткой ресурсов, ограниченная очередь кадров, позиция ролика, приглушение игровых звуков. |
| `video/VideoDecoder`, `video/FfmpegVideoDecoder`, `video/VideoLibraries` | Контракт декодера с разделением видео и аудио, чтение MP4 из локального файла, изолированная загрузка JavaCV и JNI. |
| `video/VideoAudio`, `video/VideoRenderer` | Вывод PCM через Java Sound и повторное использование OpenGL-текстуры. |
| `network/CoreNetwork`, `network/VideoControlMessage`, `network/VideoFeedbackMessage`, `network/CommonProxy`, `client/hud/ClientProxy` | Регистрация на существующем Forge SimpleNetworkWrapper и передача событий в правильный поток. Мультимедийная часть и JNI загружаются клиентом по запросу. |

## Библиотеки и установка

JavaCV и JavaCPP **1.5.10**, FFmpeg **6.1.1-1.5.10**. Используются пять отдельных файлов — JavaCV, JavaCPP, FFmpeg и два JAR с нативными компонентами JavaCPP и FFmpeg для Windows x86_64. Нативные DLL извлекаются в кеш JavaCPP. Полный `javacv-platform` не используется.

`prepareVideoRuntime` подготавливает `build/video-client/frrnq_video_libs/`. Для установленного клиента папку `frrnq_video_libs` нужно положить рядом с `mods` в рабочей директории игры. `runClient` вызывает `installVideoDevRuntime` для `run/frrnq_video_libs`. Серверу эти библиотеки не нужны. HTTP-клиент — `HttpsURLConnection` из Java 8.

## Команды

Все команды `/fcore video` доступны OP 2+ и серверной консоли.

| Команда | Действие |
|---|---|
| `/fcore video preload <url>` | Скачать и подготовить MP4, затем ждать запуска. |
| `/fcore video play <url>` | Подготовить MP4 и автоматически назначить запуск. |
| `/fcore video start` | Запустить подготовленную сессию с учётом готовности клиентов. |
| `/fcore video stop` | Отменить загрузку, подготовку или воспроизведение. |
| `/fcore video mode <fullscreen\|corner\|overlay>` | Переключить режим у участников, в том числе во время показа. |
| `/fcore video opacity <0–100>` | Настроить непрозрачность Overlay. По умолчанию 70%. |
| `/fcore video volume <0–100>` | Настроить относительную громкость с учётом Minecraft. По умолчанию 80%. |
| `/fcore video status` | Показать состояние, домен источника, позицию и счётчики участников. |

Локальная разработка в одиночном мире с разрешёнными командами: `/fcorevideotest play <имя.mp4>`, `stop`, `mode fullscreen/corner/overlay`, `opacity <0–100>`, `volume <0–100>`, `status`. Файлы лежат в `frrnq_videos/` клиента. При активной глобальной сессии локальные тестовые команды блокируются.

## Протокол и синхронизация

- **ID 5, сервер → клиент, `VideoControlMessage`.** Заголовок — один байт типа и `long sessionId`. `STATE` передаёт назначенное время старта, длительность в микросекундах, режим, прозрачность, громкость и URL до 2048 байт. URL присутствует при создании сессии и входе игрока. `STOP` завершает сессию, `CLOCK` возвращает метку запроса и монотонное время сервера.
- **`PREPARATION` в ID 5.** После общего заголовка идут 13 байт в таком порядке: байт фазы, три `int` для общего числа участников, готовых и клиентов с ошибками. Число готовящихся вычисляется из этих полей. Фаза `HIDDEN` снимает панель. Статистика отправляется только получателям с серверным OP 2+, проверка изменений выполняется раз в 500 мс. Панель скрывается с началом трансляции. Обычные игроки видят только воспроизведение.
- **ID 6, клиент → сервер, `VideoFeedbackMessage`.** Пакет длиной 17 байт — байт типа, `long sessionId`, `long data`. `DOWNLOADED` сообщает о готовности файла, `READY` передаёт длительность после декодирования первого кадра и подготовки аудиобуфера, `ERROR` передаёт категорию ошибки, `CLOCK` запрашивает время. Сервер привязывает отчёт к отправителю и ограничивает частоту. Ошибки остаются в локальном логе и учитываются сервером.
- Клиент применяет сообщения через `Minecraft.addScheduledTask` после проверки текущего соединения. Сервер обрабатывает клиентский отчёт через `WorldServer.addScheduledTask`. Устаревшие ID сессий игнорируются.
- Сервер ждёт готовности до 30 секунд для `play` или запрошенного `start`. При наличии готовых клиентов старт назначается через 2 секунды. Если готовых нет, запуск отменяется. Сервер использует максимальную допустимую длительность среди готовых клиентов на момент назначения старта.
- Клиент сопоставляет `System.nanoTime()` двух сторон по RTT и середине интервала запроса. Поздний старт использует `setVideoTimestamp()` и `setAudioTimestamp()` в отдельных проходах FFmpeg. При отставании более 750 мс возможна повторная подготовка с перемоткой с ограничением частоты. Завершившаяся сессия пропускается. Отключение отменяет клиентскую подготовку и освобождает ресурсы.

## Воспроизведение, загрузка и безопасность

- MP4 с H.264 и моно или стерео AAC, до 30 FPS и 120 секунд. Ролики без аудио поддерживаются. Выходной кадр ограничен длинной стороной 1920 и площадью 2 073 600 пикселей. Крупные кадры уменьшаются пропорционально, остальные сохраняют размер. В `FfmpegVideoDecoder` отдельно задан защитный предел нативного декодера в 16 777 216 пикселей.
- `FULLSCREEN` вписывает изображение с чёрными полосами при необходимости, `CORNER` использует верхний правый угол, `OVERLAY` сохраняет прозрачность. Рендер учитывает SAR и метаданные поворота, использует GL_LINEAR и выполняется до HUD Minecraft/Forge. Игровой ввод и существующие HUD продолжают работать поверх видео.
- Независимые фоновые проходы декодируют изображение и звук. PCM копируется в ограниченную очередь и передаётся выделенному потоку Java Sound как signed 16-bit little-endian PCM. Цель предзаполнения 400 мс, запрашиваемый буфер линии 500 мс. Видео следует позиции фактически проигранных сэмплов, а при опустошении буфера ждёт дозаполнения. Для роликов без звука используются монотонные часы. На время показа громкость игры снижается до 25% от текущей и восстанавливается после остановки без записи в `options.txt`.
- Список `allowedDomains` в `config/frrnqserverscore-video.cfg` по умолчанию пуст. На сервере и клиенте указываются точные имена хостов, включая хосты редиректов. Разрешён HTTPS на порту 443. Клиент разрешает DNS, блокирует непубличные и локальные адреса, привязывает TCP к проверенному IP и оставляет проверку сертификата по имени хоста. FFmpeg открывает локальный файл.
- Загрузка идёт в `.part` с проверкой реального размера и очисткой после отмены. Кеш `frrnq_videos/cache/` использует SHA-256 для имён, ETag или Last-Modified для перепроверки и удаление старых записей. Лимиты 128 МиБ на файл и 512 МиБ на кеш. Секретные параметры URL не включаются в статус и сообщения мода.

## Исправленные ошибки и проверка

- Ванильная загрузка DynamicTexture возвращала GL_NEAREST каждый кадр. VideoRenderer теперь обновляет одну текстуру с GL_LINEAR на обоих фильтрах и восстанавливает состояние GL.
- Старый звуковой путь использовал общий поток декодирования и записи PCM и отбрасывал PCM при отставании свыше 40 мс. Отдельный вывод PCM и часы аудиолинии проверены воспроизведением и принудительным опустошением буфера.
- Отключение при `preload` зафиксировано в `run/logs/latest.log` как `Unexpected video packet data`. `toBytes()` записывал 13 байт для `PREPARATION`, а `fromBytes()` их оставлял непрочитанными. Исправление декодирует поля симметрично и проверяет размер, фазу и счётчики.
- Проверены загрузка MP4 и кеш с HTTP 304, подготовка и перемотка реального декодера через LaunchWrapper, декодирование разных пропорций, SAR и поворот, round-trip пакетов и сценарии `preload / play / start / stop / status` в тестовом серверном окружении. Игровую работоспособность существующих механик подтвердил пользователь.

## Решение по YouTube

В fSC 1.3 VideoPlayer поддерживает локальные MP4 и прямые HTTPS-ссылки на MP4. Интеграция YouTube закрыта по результатам проверки MCEF Legacy 1.43, 1.50 и JCEF Maven 152.0.6. Для рассмотренных сборок безопасность браузера не подтверждена. В частности, JCEF Maven принудительно отключает песочницу, а входящая в его релиз ветка CEF 7977 снята с поддержки. [Исходники JCEF](https://github.com/chromiumembedded/java-cef/blob/17e805a/native/context.cpp) · [Статус веток CEF](https://github.com/chromiumembedded/cef/blob/master/docs/branches_and_building.md#legacy-release-branches-unsupported).

`VideoDomains.check` отклоняет хосты `youtube.com`, `youtu.be` и `youtube-nocookie.com` с поддоменами до проверки списка разрешённых доменов. Команды `play` и `preload` завершаются сообщением «YouTube не поддерживается. Используйте прямую HTTPS-ссылку на MP4-файл» до вызова `VideoSessions.prepare`. Тот же валидатор применяется клиентом к исходным ссылкам и целям редиректов.

Папка `frrnq_videos/` исключена из Git целиком, включая локальные MP4, файлы кеша, метаданные и временные `.part`. Команды и настройки описаны в [README.md](README.md#videoplayer), изменения релиза — в [RELEASE_NOTES_1.3.md](RELEASE_NOTES_1.3.md).
